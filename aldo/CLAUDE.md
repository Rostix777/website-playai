# Aldo — настольный AI-бычок Freedom

> Контекст проекта для разработки. Временно лежит в `aldo/` репозитория сайта; при создании `aldo-firmware` перенести в его корень как `CLAUDE.md`.

---

## 1. Что делаем

**Aldo** — маленький настольный AI-компаньон в виде зелёного бычка (маскот Freedom). Стоит на столе, подключён к интернету, показывает котировки, цены и новости, отвечает голосом и умеет запускать операции через AI SuperApp.

Ключевые принципы:

- **Тонкий клиент.** Устройство — это «лицо, голос и экран». Вся логика, LLM и агенты живут на бэкенде.
- **Без Android.** Жёсткого требования к Android нет. Платформа — ESP32-S3.
- **Портативность.** Бычок снимается с док-станции и работает от батареи.
- **Скины.** Сменные напечатанные тела и аксессуары (рога, наушники, шапки) — часть продукта и монетизации.
- **Безопасность операций.** Публичные данные — без авторизации. Любые операции по счёту — только с подтверждением в телефоне.

## 2. Функциональные требования

| # | Функция | Авторизация |
|---|---------|-------------|
| F1 | Показ котировок, цен, новостей (тикер на экране) | Не нужна — открытые API |
| F2 | Голосовой вопрос → ответ голосом + анимация | Не нужна для публичных данных |
| F3 | Запуск «сложных API» (аналитика, агенты) через голос | Через бэкенд AI SuperApp |
| F4 | Операции по счёту (ордера и т. п.) | Подтверждение в SuperApp на телефоне |
| F5 | Уведомления (ценовые алерты, новости) | После привязки к аккаунту |
| F6 | Реакции на касания и движение (тап, взяли в руки) | — |
| F7 | Привязка устройства к аккаунту через QR | Device pairing |

## 3. Архитектура

```
┌──────────────────────┐        ┌──────────────────────────────┐
│  Aldo (ESP32-S3)     │        │  Бэкенд AI SuperApp          │
│  - экран / лицо      │◄──────►│  - AI-агент (LLM)            │
│  - микрофон/динамик  │  WSS   │  - MCP-инструменты           │
│  - тач, IMU          │        │    (mcp.tradernet.com и др.) │
│  - Wi-Fi 2.4 ГГц     │        │  - pairing / CIBA            │
└─────────┬────────────┘        └──────────────┬───────────────┘
          │ HTTP/WS (публичные                 │ push
          │ котировки, без ключа)              ▼
          ▼                          ┌──────────────────────┐
  ┌──────────────────┐               │ AI SuperApp (телефон)│
  │ Открытые API     │               │ - подтверждение      │
  │ котировок/новостей│              │   биометрией         │
  └──────────────────┘               └──────────────────────┘
```

### 3.1 Уровни

- **Устройство.** Рисует UI, стримит аудио на бэкенд, проигрывает ответы, показывает состояния. Ключи и токены пользователя на устройстве **не хранятся**.
- **Публичные данные.** Котировки и новости бычок может забирать напрямую из открытых API компании (без ключа) — бэкенд для этого не обязателен.
- **Бэкенд AI SuperApp.** Принимает голос/текст, AI-агент вызывает MCP-инструменты, возвращает ответ (текст + TTS-аудио + команда состояния для лица). Новые «сложные API» добавляются на сервере без перепрошивки.
- **Телефон.** Единственное место подтверждения операций.

### 3.2 Потоки авторизации

**Привязка устройства (OAuth 2.0 Device Authorization Grant, RFC 8628):**
1. Бычок запрашивает у бэкенда `device_code` + `user_code`.
2. На экране показывается QR.
3. Пользователь сканирует QR в AI SuperApp → подтверждает.
4. Бэкенд выдаёт устройству токен привязки (device-scoped, без прав на торговлю).

**Операции по счёту (CIBA-подобный поток):**
1. Пользователь голосом: «Купи 10 Apple».
2. Бэкенд/агент формирует намерение (intent) ордера.
3. Пуш в SuperApp → пользователь подтверждает биометрией.
4. Бэкенд исполняет, бычок показывает `success` / `error`.

### 3.3 Безопасность устройства

- Secure Boot + Flash Encryption (ESP-IDF).
- Уникальная идентичность устройства (сертификат/ключ, прошитый при производстве) — для rate limiting и учёта, даже если сами данные публичные.
- OTA-обновления только подписанными образами.
- Торговые MCP-инструменты на бэкенде закрыты обязательным подтверждением с телефона.

## 5. Физический дизайн

Концепция по мотивам @creativechance:

- **Голова.** Модуль Waveshare вставляется в напечатанную оболочку. Рога и уши — съёмные детали (скины).
- **Тело.** Зелёная «игрушечная» фигурка, голова садится сверху. Внутри — USB-C удлинитель от модуля к базе.
- **Док.** Подставка с USB-C разъёмом, бычок надевается сверху и заряжается. Снял — портативный.

Два варианта лица:
1. **Всё на экране.** Лицо целиком на дисплее, напечатаны только рога и уши.
2. **Гибрид.** Зелёная печатная накладка с вырезом под чёрную «маску», нос с ноздрями напечатан поверх нижней части экрана. Экран показывает только глаза и иконки.

Ограничения при моделировании:
- Не перекрывать отверстия динамика и микрофонов.
- Доступ к кнопкам и USB-C.
- Инструменты: Fusion 360 / Onshape (механика), Blender (мягкие формы). Печать: Bambu Lab A1 mini или JLC3DP.

## 6. Персонаж и состояния (UI state machine)

Дизайн готов: 16 состояний + 4 агента, светлая и тёмная версии. **На AMOLED использовать тёмную** — чёрные пиксели выключены, лицо «светится», экономия батареи.

| Состояние | Триггер |
|---|---|
| `appear` | Включение / пробуждение |
| `idle` | Ожидание (+ тикер котировок) |
| `attention` | Устройство взяли в руки (IMU) |
| `notification` | Ценовой алерт, новость |
| `tap_once` (2 варианта) | Одиночное касание |
| `tap_many` (2 варианта) | Много касаний подряд («закружилась голова») |
| `listening` | Идёт запись голоса |
| `thinking` | Ждём ответ бэкенда |
| `typing` | Бэкенд формирует ответ |
| `working` | Агент выполняет запрос через MCP |
| `success` | Операция подтверждена / выполнена |
| `positive` | Рост портфеля / хорошая новость |
| `empathy` | Падение / плохая новость |
| `error` | Ошибка, отказ, нет сети |

Агенты (иконка-аксессуар показывает, кто отвечает):

| Агент | Роль |
|---|---|
| `agent_support` | Поддержка клиента |
| `agent_analyst` | Аналитика |
| `agent_trader` | Торговые операции |
| `agent_docs` | Документы |

### 6.1 Ассеты от дизайнера

- Каждое состояние — **Lottie (JSON)** или последовательность PNG на чёрном фоне, **466×466**.
- Отдельно «живой» idle: моргание, взгляд в стороны.
- Палитра: зелёный бычок (#0BAE3E-ish), тёмно-зелёные рога/акценты, чёрная маска.

## 7. Прошивка

### 7.1 Стек

- **ESP-IDF** (C/C++), VS Code + плагин ESP-IDF.
- **LVGL 9** — UI. Lottie через встроенный `lv_lottie` (ThorVG). Если не хватит памяти/производительности — fallback на PNG-спрайты.
- **xiaozhi-esp32** — open-source голосовой AI-ассистент для ESP32-S3 (стриминг аудио, MCP). Форкнуть и перенаправить на свой бэкенд вместо написания голосового контура с нуля. Проверить, что плата Waveshare 1.75C есть в списке поддерживаемых.
- Wi-Fi provisioning (BLE или SoftAP), NVS для настроек, OTA.

### 7.2 Модули

```
main/
  app_main.c          — инициализация, главный цикл
  display/            — драйвер AMOLED, тач, LVGL
  face/               — state machine лица, проигрывание анимаций
  audio/              — микрофон, динамик, кодек
  imu/                — детекция «взяли в руки», тряска
  net/                — Wi-Fi, provisioning, WebSocket к бэкенду
  market/             — клиент открытых API котировок/новостей
  pairing/            — Device Authorization Grant, QR
  ota/                — обновления
```

### 7.3 Протокол устройство ↔ бэкенд (черновик)

WebSocket, JSON-сообщения + бинарные аудио-фреймы.

```jsonc
// устройство → бэкенд
{ "type": "hello", "device_id": "...", "fw": "0.1.0" }
{ "type": "audio_start" }           // далее бинарные Opus-фреймы
{ "type": "audio_end" }
{ "type": "event", "name": "tap_many" }

// бэкенд → устройство
{ "type": "state", "value": "thinking" }
{ "type": "agent", "value": "agent_trader" }
{ "type": "tts_start" }             // далее бинарные Opus-фреймы
{ "type": "tts_end" }
{ "type": "display", "ticker": [{ "s": "AAPL", "p": 231.4, "c": 1.2 }] }
{ "type": "notify", "title": "...", "state": "notification" }
```

> Это предложение, финальный контракт согласовать с бэкенд-командой.

## 8. План (майлстоуны)

| # | Цель | Результат |
|---|---|---|
| M0 | Окружение | ESP-IDF стоит, «hello world» залит на плату |
| M1 | Лицо | 16 состояний на экране, переключение касанием |
| M2 | Данные | Wi-Fi + тикер котировок из открытого API |
| M3 | Голос | Форк xiaozhi → голосовой запрос в свой бэкенд, ответ голосом |
| M4 | Сенсоры | IMU → `attention`, тапы → `tap_once`/`tap_many` |
| M5 | Привязка | QR + Device Authorization Grant с SuperApp |
| M6 | Операции | Ордер голосом → подтверждение в телефоне → `success`/`error` |
| M7 | Корпус | Напечатанные голова, тело, док |
| M8 | Демо | Показ руководству |

## 10. Быстрый старт на ПК

1. Установить VS Code + расширение **ESP-IDF** (Espressif), выбрать актуальную стабильную версию ESP-IDF.
2. Клонировать `xiaozhi-esp32` и пример Waveshare для ESP32-S3-Touch-AMOLED-1.75C (вики Waveshare).
3. Собрать и прошить пример Waveshare → убедиться, что экран, тач и звук работают.
4. Создать репозиторий `aldo-firmware`, положить этот файл в корень.
5. Начать с M1: вывести `idle` и переключение состояний по тапу.

Нужен USB-C кабель **с передачей данных**, Wi-Fi 2.4 ГГц.
